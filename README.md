This is a collection of temperature (and in some cases, humidity and/or pressure) sensors using ESP microcontrollers. They're all pretty simplistic, essentially just periodically querying then publishing the readings to an MQTT broker, primarily for use with HA. I basically had a couple of spare ESPs knocking around and chose to make use of them in this manner.

The initial couple of modules were built around the [DHT22 sensor](https://randomnerdtutorials.com/esp32-dht11-dht22-temperature-humidity-sensor-arduino-ide/). These are pretty cheap and cheerful sensors (I picked up 3 for about £5 off eBay) which provide temperature and humidity readings. I had one stuck in the hallway and the other in the loft (for various reasons I won't go on about here).

What I've discovered though is that those DHT sensors are pretty unreliable, after a random period of time (could be anything from hours to days/weeks), they'll just stop reading data and continually throw an _Sensor Not Ready_ error. Powering them from 5V (instead of 3.3V as is suggested elsewhere online) does seem to improve things a tad but they're still pretty cack. I've also tried a couple of different DHT library packages and as a last result, triggered a soft reboot when this event occurs, neither of which has really helped. Only a hard power cycle seems to recover the thing.

As such I've now re-worked the boards to use [BME 280 sensors](https://randomnerdtutorials.com/esp32-bme280-arduino-ide-pressure-temperature-humidity/) instead. Those are a little more expensive however on that basis at least, I'm hopeful they'll prove more reliable in the long run. 

The module using the BMP280 sensor (which is near enough identical to the BME except it lacks the humidity sensor) is slightly different in that it is designed to run off a 18650 rechargeable battery. This variant uses the C6 supermini which allows the battery to be connected directly and be charged in-situ. The software is likewise somewhat different: it makes use of the ESP's deep sleep mode (which should consume ~77uA when asleep), only waking up to publish the latest readings every 15 minutes. It also publishes a sensor for the battery voltage level, this needs to be connected to one of the ADC capable GPIO lines via a 2:1 voltage divider.

I actually bought the BMP sensors by mistake thinking they were the BME variants....
